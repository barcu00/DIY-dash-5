# OpenDash v0.1 Design

## Goal
Build the first hardware-validation firmware for Waveshare ESP32-S3-Touch-LCD-5 (non-B, 800x480) as the foundation for an ECUMaster motorsport dashboard.

## Hardware
- Waveshare ESP32-S3-Touch-LCD-5 (non-B)
- 800x480 RGB LCD, ST7262
- GT911 capacitive touch
- ESP32-S3, 16 MB flash, 8 MB OPI PSRAM
- CAN reserved for v0.2: TX GPIO15, RX GPIO16

## Stack
- PlatformIO
- Arduino-ESP32
- ESP32_Display_Panel
- LVGL 8.4
- C++17
- GitHub Actions

## v0.1 Scope
### Included
- LCD, touch and PSRAM bring-up
- LVGL integration
- DASH / DIAG / TRACK screens
- touch navigation
- high-contrast motorsport theme
- deterministic mock telemetry
- Serial startup diagnostics
- GitHub Actions build + firmware artifacts

### Excluded
- live ECUMaster CAN
- SD logging
- Wi-Fi/OTA
- NVS settings
- real lap timing
- SquareLine project export

## Architecture
```text
src/
  main.cpp
  app/app.cpp
  app/app.h
  board/board_display.cpp
  board/board_display.h
  telemetry/vehicle_state.h
  telemetry/mock_telemetry.cpp
  telemetry/mock_telemetry.h
  ui/ui.cpp
  ui/ui.h
```

The UI consumes engineering-unit values from `VehicleState`. Hardware and future CAN decoding must never be accessed directly from UI code.

## VehicleState
```cpp
struct VehicleState {
    uint16_t rpm;
    int8_t gear;
    float speed_kph;
    float map_bar;
    float lambda;
    float clt_c;
    float iat_c;
    float oil_pressure_bar;
    float oil_temp_c;
    float fuel_pressure_bar;
    float battery_v;
    float tps_percent;
};
```

## Screens
### DASH
Top shift-light bar, large RPM and gear, speed, MAP/boost, lambda, CLT, IAT, oil pressure, oil temp, fuel pressure, battery, TPS, and bottom DASH/DIAG/TRACK navigation.

### DIAG
Firmware version, data source MOCK, resolution, touch status, PSRAM, heap, uptime, UI update counter, CAN shown explicitly as DISABLED.

### TRACK
Large gear/RPM, shift bar, speed, MAP, lambda, oil pressure, CLT and demo lap/session fields clearly labelled MOCK.

## Mock telemetry
Non-blocking deterministic periodic values within realistic ranges. It exists to exercise rendering and screen refresh, not to model engine physics.

## Error handling
- display init failure stops normal UI startup and logs the reason
- touch failure still allows display rendering and is reported on Serial/DIAG
- PSRAM is preferred for LVGL buffers; safe fallback is allowed only if allocation succeeds

## Testing
- host/native unit test for mock telemetry bounds and deterministic behavior
- firmware compile on every push/PR
- v0.1 is not considered hardware-validated until tested on the actual board

## CI artifacts
Publish from `.pio/build/waveshare_5/` when present:
- firmware.bin
- bootloader.bin
- partitions.bin

## Definition of Done
- modular source tree exists
- native tests pass
- firmware build is green in GitHub Actions
- firmware artifacts are published
- user confirms LCD/touch/mock UI on hardware
- no live CAN feature is represented as working
