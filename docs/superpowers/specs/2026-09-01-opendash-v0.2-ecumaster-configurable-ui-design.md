# OpenDash v0.2 ECUMaster + rusEFI Configurable UI Design

## Goal

Extend the validated OpenDash v0.1 firmware for Waveshare ESP32-S3-Touch-LCD-5 (non-B, 800x480) with live CAN data, a typed parameter registry, configurable dashboard tiles, per-parameter warnings, gesture-only screen navigation, user-selectable motorsport icons, on-screen configuration and persistent settings in NVS.

## Core architecture

```text
CAN driver
   -> ECU decoder
      -> Parameter Registry
         -> Alarm Manager
         -> Tile Engine
            -> DASH / TRACK / DIAG / SETTINGS
```

Supported data sources for the architecture:
- MOCK
- ECUMASTER
- RUSEFI

The user-facing name is always `CAN`. `TWAI` may appear only inside the ESP32 low-level CAN implementation.

## Hardware and stack

- Waveshare ESP32-S3-Touch-LCD-5 non-B
- 800x480 RGB LCD
- ESP32-S3
- CAN TX GPIO15
- CAN RX GPIO16
- onboard CAN transceiver
- PlatformIO + Arduino-ESP32
- ESP32_Display_Panel
- LVGL 8.4
- ESP32 NVS

## Navigation

There is no permanent navigation bar and no page-position indicator.

Screens are changed using horizontal swipe gestures only:

```text
DASH <-> TRACK <-> DIAG <-> SETTINGS
```

Requirements:
- swipe left/right changes the top-level screen
- no visible DASH/DIAG/TRACK/SETTINGS buttons
- no dots, page number or other screen indicator
- vertical scrolling inside SETTINGS must remain usable
- horizontal gesture detection in scrollable settings screens must not trigger from ordinary vertical scrolling
- long press on a tile must remain distinct from swipe

Removing the v0.1 navigation bar frees the bottom display area for telemetry.

## Parameter Registry

Every supported ECU value receives a stable compile-time `ParameterId`.

```cpp
struct ParameterDescriptor {
    ParameterId id;
    const char* name;
    const char* short_name;
    const char* unit;
    uint8_t decimals;
    float display_min;
    float display_max;
    bool is_boolean;
    IconId default_icon;
};

struct ParameterValue {
    float value;
    bool valid;
    uint32_t updated_ms;
};
```

The UI, warnings and persistent tile configuration refer only to stable parameter IDs. Raw CAN byte positions and scaling never appear in UI code.

OpenDash v0.2 supports the complete standard EMU Black stream at configurable base ID, default `0x600`, covering frames `0x600` through `0x607`.

The decoder must cover all values and status bits present in the current official ECUMaster stream documentation, including at minimum:

### Engine / load
- RPM
- TPS
- MAP / boost
- boost target
- injector pulse width
- ignition angle
- dwell

### Temperature
- IAT
- CLT
- oil temperature
- ECU temperature
- EGT1
- EGT2

### Pressure
- barometric pressure
- oil pressure
- fuel pressure

### Lambda / fuel
- lambda
- lambda target
- lambda correction
- ethanol content
- fuel used

### Vehicle / drivetrain
- vehicle speed
- gear
- DBW position
- DBW target

### Electrical / analog
- battery voltage
- AIN1 through AIN6
- PWM1
- PWM2

### Traction / limiter / torque management
- TC differential RPM raw
- TC differential RPM filtered
- TC torque reduction
- pit limiter torque reduction

### Status / boolean flags
- ECU error/status flags
- launch control
- anti-lag
- gear cut
- traction control
- pit limiter
- brake input
- fuel pump
- fan
- nitrous
- CAN switch/status bits

Exact offsets, signedness, scaling and units must be implemented from the current official ECUMaster documentation and covered by decoder fixture tests.

## rusEFI mapping

The Parameter Registry and icon catalog must cover all useful telemetry channels exposed by the current rusEFI CAN/DBC definition that can reasonably be displayed on a motorsport dash.

The rusEFI decoder is a separate adapter and must normalize rusEFI values into the same `ParameterId` model where a semantic equivalent exists. rusEFI-only values receive dedicated IDs.

The implementation plan must first freeze the exact supported rusEFI DBC revision/source and generate fixture tests from that source before production decoder code is written.

## CAN configuration

Editable from SETTINGS:
- source: MOCK / ECUMASTER / RUSEFI
- bitrate: 125 / 250 / 500 / 1000 kbit/s
- ECUMaster base ID, default `0x600`
- rusEFI base/profile settings according to the selected supported DBC/profile
- frame timeout, default 500 ms
- live CAN state
- received frame counter
- invalid/lost frame counter where available

## CAN stale-data behavior

If the selected real ECU source does not receive valid frames inside the timeout:
- CAN status becomes LOST/OFFLINE
- parameters from that CAN source become invalid
- stale values render as `---`
- the UI continues operating
- parameter alarms using invalid data are suppressed
- a dedicated CAN LOST alarm may remain active

## Configurable tiles

Every secondary telemetry tile is configurable. Fixed primary widgets such as RPM and gear may remain fixed where required by a chosen layout.

```cpp
enum class ValueFormatMode : uint8_t {
    Native,
    Lambda,
    Afr,
};

struct TileConfig {
    ParameterId parameter;
    bool visible;
    bool custom_label_enabled;
    char custom_label[16];
    bool custom_icon_enabled;
    IconId icon;
    ValueFormatMode format_mode;
};
```

### Tile editing

Long press opens the tile editor with:
- displayed parameter
- visible / hidden
- optional custom label
- icon mode: default / custom / none
- icon picker
- value format where applicable
- warning configuration shortcut
- save / cancel

### Tile hiding

Every tile can be hidden independently. Hidden tiles do not consume visible layout content.

Hiding a tile does not disable that parameter's warning.

The layout engine must define deterministic placement rules for visible tiles so hidden tiles do not leave unintended unusable gaps where an adaptive layout is selected.

## Parameter visibility

Every registry parameter also has a user presentation setting controlling whether it appears in ordinary tile parameter pickers.

A hidden parameter:
- remains available internally to decoders and warning logic
- may keep an active warning
- is omitted from normal parameter-selection lists
- can be restored from SETTINGS -> PARAMETERS

This is separate from hiding a tile.

## Icon system

OpenDash includes a purpose-built, simple, high-contrast motorsport icon library.

Requirements:
- an icon or meaningful generic icon category exists for every displayable ECUMaster parameter
- an icon or meaningful generic icon category exists for every displayable rusEFI parameter
- icons are optimized for readability on a 5-inch 800x480 display
- simple line/solid motorsport style, avoiding decorative detail
- parameter descriptor provides the default icon
- every tile can select any icon from the library
- every tile can disable its icon
- icons are stored as LVGL-compatible assets

Core icon families include RPM, speed, gear, throttle, boost/MAP, pressure, temperature, oil, fuel, lambda/AFR, injector, ignition, battery, ECU, analog input, PWM, DBW, traction, launch, anti-lag, limiter, brake, fan, nitrous, CAN, warning, lap/time and generic sensor/status icons.

## Lambda / AFR display

Lambda-family parameters can be rendered as lambda or AFR on a per-tile basis.

Formula:

```text
AFR = lambda * stoichiometric_AFR
```

SETTINGS provides fuel stoichiometric AFR configuration with presets plus custom value.

Initial presets:
- gasoline: 14.7
- E85: editable preset value
- ethanol: editable preset value
- custom

The stored value used for calculation is explicit and user-configurable. Lambda remains the preferred ECU-independent representation; AFR display is a presentation conversion only and must never alter the registry's native lambda value or warning calculations unless a warning is explicitly configured in AFR presentation units.

## Warning system

Each parameter supports:
- OFF
- LOW
- HIGH
- RANGE
- RPM_CURVE where enabled

```cpp
enum class WarningMode : uint8_t {
    Off,
    Low,
    High,
    Range,
    RpmCurve,
};

struct WarningConfig {
    WarningMode mode;
    bool enabled;
    float warning_low;
    float warning_high;
    float critical_low;
    float critical_high;
    float hysteresis;
    uint16_t delay_ms;
    bool fullscreen_critical;
};
```

Alarm states:
- NORMAL
- WARNING
- CRITICAL
- INVALID

UI behavior:
- WARNING: amber/yellow styling
- CRITICAL: red styling
- optional full-screen critical overlay
- INVALID: `---`

Hidden tiles and parameters may still generate warnings if their warning remains enabled.

## RPM-dependent oil pressure warning

Oil pressure requires an editable RPM curve of up to 8 points:

```cpp
struct RpmWarningPoint {
    uint16_t rpm;
    float min_value;
};
```

The alarm manager linearly interpolates between points and clamps below/above the configured RPM range.

## Persistence

Store in ESP32 NVS:
- selected data source
- CAN configuration
- DASH tile configuration
- TRACK tile configuration
- tile visibility
- parameter picker visibility
- custom labels
- selected/custom icons
- lambda/AFR presentation mode
- stoichiometric AFR setting
- warning configurations
- oil-pressure RPM curve

Use a schema version and safe defaults on missing/incompatible data.

Factory reset removes OpenDash-owned configuration only.
