# OpenDash v0.2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add live ECUMaster and rusEFI CAN telemetry, a typed Parameter Registry, configurable/hidden tiles and parameters, gesture-only navigation, icon selection, Lambda/AFR presentation, persistent settings and warning management to the validated OpenDash v0.1 firmware.

**Architecture:** The CAN driver feeds source-specific ECU decoders. Decoders normalize values into a typed Parameter Registry consumed by the Alarm Manager and Tile Engine. UI/settings never depend on raw frame layouts. The work is split into three independently testable phases: core+ECUMaster, UI/config/warnings/icons, then rusEFI.

**Tech Stack:** PlatformIO, Arduino-ESP32, ESP32_Display_Panel, LVGL 8.4, ESP32 NVS, ESP32 CAN/TWAI low-level driver, C++17, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-09-01-opendash-v0.2-ecumaster-configurable-ui-design.md`

## Global Constraints
- Product name is `OpenDash`; no user-facing legacy branding references.
- User-facing bus terminology is `CAN`; `TWAI` may appear only in the low-level driver.
- Target board: Waveshare ESP32-S3-Touch-LCD-5 non-B, 800x480.
- Existing LCD/touch/PSRAM bring-up must remain unchanged unless required for integration.
- Top-level navigation is horizontal swipe only: DASH <-> TRACK <-> DIAG <-> SETTINGS.
- No visible navigation bar, page dots, page number or other page-position indicator.
- Long press opens tile editing and must not be interpreted as swipe.
- Parameter IDs are stable compile-time values and are persisted instead of labels.
- Raw CAN scaling never appears in UI or warning code.
- Every secondary tile can be hidden; parameter-picker entries can also be hidden independently.
- Hidden tiles/parameters may still generate warnings.
- Lambda remains the native registry value; AFR is presentation-only using configurable stoichiometric AFR.
- ECUMaster profile default: base ID `0x600`, standard IDs, nominal 1 Mbit/s, frames through `0x607`.
- NVS configuration uses a schema version and safe defaults.
- TDD is required for pure logic and decoders.
- CI must pass native tests, target firmware build and artifact upload.

## Hardware acceptance after CI

The physical-board test must verify:

1. LCD/touch/PSRAM behavior remains stable.
2. No navigation bar or page indicator is visible.
3. Swipe left/right changes top-level screens.
4. SETTINGS vertical scrolling does not accidentally swipe pages.
5. Long press edits a tile.
6. A tile can be hidden/restored.
7. A parameter can be hidden/restored in picker lists.
8. An icon can be changed or disabled per tile.
9. Lambda can be displayed as Lambda or AFR using configured stoich AFR.
10. Configuration survives power cycle.
11. Live ECUMaster values decode correctly.
12. rusEFI values decode correctly for the frozen profile.
13. CAN disconnect triggers LOST/invalid values.
14. Warnings remain active even when the corresponding tile is hidden.
15. Oil-pressure RPM-dependent warning evaluates correctly.
