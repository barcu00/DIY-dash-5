# OpenDash v0.2 Render-Parity UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rebuild the physical 800x480 OpenDash interface to match the approved render structure and density, with a permanent RPM/shift-light strip, three independent 4x3 DASH pages, reliable raw-touch swipe navigation, and render-style TRACK/DIAG/SETTINGS screens while preserving the working CAN/ECUMaster/NVS/alarm backend.

**Architecture:** Keep `App`, CAN, ECUMaster decoding, Parameter Registry, Alarm Manager and NVS as backend sources of truth. Replace the monolithic presentation code with focused UI widgets/pages and move root-page navigation from LVGL `LV_EVENT_GESTURE` to a pure raw-touch recognizer fed by the GT911 callback. Persistent configuration becomes schema v3 with three DASH profiles and an explicit v2 migration path that preserves non-UI settings.

**Tech Stack:** C++17, PlatformIO, Arduino-ESP32 on ESP32-S3, LVGL 8.4, ESP32_Display_Panel/GT911, NVS Preferences, Unity native tests.

**Spec:** `docs/superpowers/specs/2026-09-02-opendash-v0.2-render-parity-ui-design.md`

## Global Constraints

- Target is Waveshare ESP32-S3-Touch-LCD-5 non-B, native 800x480 landscape.
- The approved render is the visual source of truth, except the complete removal of logo/time/Wi-Fi/CAN/battery header content.
- Top 48 px of DASH pages are reserved for real RPM + 12-segment shift-light.
- No visible page dots, page numbers, root navigation buttons, or instructional `Long press a tile to edit` text.
- Root ring is `Dash1 -> Dash2 -> Dash3 -> Track -> Diag -> Settings -> Dash1`, reverse on right swipe.
- DASH pages each contain 12 independent configurable slots, total 36 persistent DASH slots.
- Do not change ECUMaster decoding, CAN pins, CAN bitrate behavior, stale-data behavior, Alarm Manager semantics, or silent-fallback policy.
- Real ECU stale/offline values remain `---`; never silently fall back to MOCK.
- No static full-screen screenshot background and no fake GPS/lap/diagnostic values.
- NVS namespace remains `opendash`; migration must preserve compatible CAN, AFR, parameter visibility and warning settings.
- Do not place complete `AppConfig` or legacy equivalents on the Arduino task stack.
- Retain asynchronous LVGL overlay destruction; never delete the object currently dispatching an event synchronously.
- Native tests must be RED before each production behavior change and GREEN before moving to the next task.
- Final delivery requires native tests, Waveshare firmware build, merged full BIN and artifact upload from the exact same HEAD.
